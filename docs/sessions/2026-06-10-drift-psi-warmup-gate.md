## Decisions
- **ADR 0017** — PSI warmup gate. (1) Threshold + predicate live in `shared.drift` (single source; binds the future fleet-PSI Lambda). (2) `compute_psi` unchanged — gate the alert, not the computation. (3) Applied at the `lambda_scorer` arming site. (4) Threshold = 150 samples (5 min = `WINDOW_SAMPLES`; ~15 obs/bin → Laplace prior a ~6% correction). (5) `score > 0.7` ungated. PO sign-off 2026-06-10 (gate location + threshold chosen via AskUserQuestion).

## Trade-offs surfaced
- **Gate the alert, not `compute_psi`** — keeps the parity-pinned return contract and the dashboards-adapter wire format intact; PSI still visibly warms up on Grafana. (Rejected: returning `None` from `compute_psi`, which would ripple into the STATE-row `latest_psi` Map and conflate "not warm" with local mode's "not computed this tick".)
- **Ungated score path** — a genuinely failing pump in its first 5 min still alerts via `score > 0.7`; only the small-sample PSI artifact is suppressed.
- **Parity by construction, not a second call site** — local mode has no alert, so there is no PSI-value divergence; the shared constant is what prevents the future fleet-PSI Lambda from diverging (north star #6).
